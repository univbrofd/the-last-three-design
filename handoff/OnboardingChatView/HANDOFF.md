# HANDOFF — OnboardingChatView（ビデオ通話 × 理想の相手が結ばれていく）

repo: `univbrofd/the-last-three-design` / branch `main`
raw base: `https://raw.githubusercontent.com/univbrofd/the-last-three-design/main/`
DS 索引: `DesignSystem/_ds_manifest.json` / 土台: `DesignSystem/USAGE_RULES.md` → `taste.md`

## タスク

登録ヒアリング画面を **チャット UI → ビデオ通話 UI** に作り替える。加えて、**通話相手の像が、答えるほど「理想の相手」の姿へ収束していき、最後にカードとして結晶する**。

既存デザイン（チャットバブル版）= `handoff/AppPrototype/OnboardingChatView.dc.html`。これを Before として Before/After を示すこと。

体験の狙い: **「面接を受けている」感覚**と、**「まだ見ぬ相手が、自分の言葉で形になっていく」実感**。ユーザーは見られている側で、相手は画面いっぱいに映り、目を合わせて質問してくる。5 分間、逃げ場がなく、しかし責められてはいない。

## 像の設計（確定事項・この画面の核）

**画面に映るのは 1 体だけ**。最初は形のない粒子の集まり（＝声だけの存在）で、AI はこの像を通して話す。答えるほど粒子が収束し、**理想の相手の姿を借りていく**。質問者と答えが同じ像に重なることが、この画面の全て。

収束は 4 段階。specimen で描き分ける:

| 段階 | いつ | 見え方 |
|---|---|---|
| **S0 無形** | 入場・名前を聞く | 粒子が散在。人型を成さない。中心にわずかな密度がある程度 |
| **S1 輪郭** | 理想の相手の話が始まる | 肩と頭部のシルエットが読める。顔はまだ無い |
| **S2 半結像** | 人柄・見た目の好みが入る | 体格・髪の量感・目のあたりの密度が出る。視線が成立する |
| **S3 結像** | 山場を越える | 人物として見える。ただし**顔の造作は最後まで描き切らない**（実在の誰かに見えてはいけない） |

- 収束の度合いが進捗そのもの。進捗バーと像は同じ情報を二重に伝える
- 発話中は収束して輪郭が締まり、傾聴中はわずかに拡散して揺らぐ（段階に関わらず）
- 黙っている間も像は動き続ける（呼吸 4s ease-in-out・微細なノイズの流れ）。静止させない
- 実写でもイラストでもない。既存の「退色・粒子」モチーフと同じ語彙で作る
- `--primary` は像の装飾に使わない（`USAGE_RULES §3`）。像は明度差と粒子密度だけで作り、灯りは進捗・CTA・選択状態にのみ点く
- 口の動き・まばたきをどのパラメータで作るか分解して示す（例: 口 = 特定領域の密度 0→1）。Flutter では音声振幅で駆動する前提
- 参照する体験は「ゲーム冒頭で博士が語りかけてくる」型（全画面・語り・文字送り・選択）。**既存キャラクターの見た目は複製しない**

## 進行（順序は変更済み）

1. **名前**（1 問だけ）— 像は S0。以降、像はユーザーを名前で呼ぶ
2. **理想の相手**（S0 → S2）— そばにいてほしい人柄 / 好みの見た目・体格 / 苦手な相手
3. **あなた自身**（S2 のまま）— 生活リズム・連絡ペース・来歴、および基本情報（生年月日 / 住まい / 身長 / 体格 / きょうだい / 写真）
4. **山場**（S2 → S3）—「許せないことを、ひとつだけ」
5. **結晶** — 像がカードへ収束し、理想の相手のカードを全画面で見せる →「待機をはじめる」

質問の矛先が 2 → 3 で「相手のこと」から「あなたのこと」へ切り替わる。**この切り替わりが伝わる表現**を設計すること（ラベル / 像の姿勢 / 字幕の見出し等、手段は問わない）。

## 要件（必須）

1. **チャットバブルを全廃**。吹き出し・左右振り分け・スクロールする会話ログを持たない
2. **ビデオ通話の画面構成** — 像が full-bleed で大きく映る。自分はインカメラの小窓（PinP）
3. **AI の発話は字幕**。1 文字ずつ送る演出前提なので、送り途中／送り完了の 2 状態が要る
4. **音声が既定、テキストでも答えられる**。キーボードに切り替えると入力欄がせり上がる。選択肢チップも残す
5. **進行が分かる** — 通話時間と `Q n / N`、そして像の収束段階

## 成果物

`.phone` 枠（402×874）に full-bleed で実配置した specimen を、シーンごと 1 ファイル:

| # | シーン | 像 | 内容 |
|---|---|---|---|
| 1 | 入場 | S0 | 暗転から粒子が集まる。`はじめに、なんと呼べばいいですか。` |
| 2 | 理想の相手 | S1 | 字幕タイプ中 + 選択肢チップ |
| 3 | 理想の相手 | S2 | 複数選択（`これで送る（2）`）+ 応答待ちのマイク待受 |
| 4 | あなた自身 | S2 | 矛先が変わったことが分かる。生年月日など非テキスト入力 |
| 5 | テキスト入力 | S2 | キーボード想定で入力欄がせり上がる |
| 6 | 山場 | S2→S3 | `許せないことを、ひとつだけ教えてください。` |

各 specimen 先頭に `@dsCard`、`_ds_manifest.json` に登録。最終は bundle で出力。

### カードについて（重要）

- カードの**紙面そのものは AI 画像生成で焼かれる 1 枚絵**。Claude Design は紙面の意匠を作らない
- 作るのは「カードを見せる画面」= 生成画像の置き場（縦長・角丸・拡大可）、余白、周辺のコピー、CTA、そして**像 → カードへの遷移演出**
- 画像が届く前の**生成中プレースホルダ**も 1 状態として要る（像がまだ結晶し切っていない見え方）

## 配置文脈（必須）

- 402×874・画面角丸 55・SafeArea 上 62（Dynamic Island 含む）/ 下 34 = `DesignSystem/preview/card.css` の `.phone`
- タップ範囲 最小 44×44pt（見た目 20px でも当たり判定 44）

## 直すべき逸脱

- 通話 UI の定番（赤い REC 点・緑の応答ボタン・赤い終了ボタン）は `USAGE_RULES §6` で禁止。録音中は `--primary` の呼吸ドットか `--text-3` の mono ラベルで表す
- **通話終了ボタンを置かない**（ヒアリングから離脱させる導線を作らない）。ミュートとキーボード切替のみ
- 現行実装に `rgba(245,241,234,.86)` 相当の素の透明度直書きが残る → `--text-1/2/3` の役割トークンに寄せる
- `--primary` は「灯り」用途のみ（進捗・主要 CTA・選択状態）。像・装飾・区切り線には使わない
- エフェクト予算 1 コンポーネント 1〜2 個（像 = 粒子 + スクリムのみ。そこにグローを足さない）
